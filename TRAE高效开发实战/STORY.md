# STORY.md — TRAE 高效开发实战（1024 济宁）

## ① 用户意图对齐

- **目标受众**：1024 程序员节济宁活动现场的技术人（一线开发者为主，部分技术负责人）。他们大多用过或正在观望 AI 编程工具，对"能不能真的提速"持怀疑态度。
- **核心目标**：讲完后希望他们相信——**TRAE 的价值不在"写得多快"，而在"把人从返工里捞出来"**；记住并当天就能照做的三件事：先写 60 秒演示脚本、并行前冻结契约、把兜底做进交付。
- **PPT 长度**：11 页（Hero 3 页：封面 / 2.6× 数据页 / 结束页，占 27%）。
- **视觉调性**：终端感、冷峻、极客、留白克制、绿色信号灯。
- **内容边界**：
  - 必讲：真实项目《人类协议 2100》的关键动作、真实实测数字（2.6× / 1.44×）、真实踩坑（Light 语言 5 个坑）。
  - 不讲：TRAE 产品功能教学、模型参数、团队管理方法。
  - 禁碰：虚构数据、虚构客户、把"规则推演"说成"AI 大模型生成"。

## ③ 页面大纲

### 01 封面 · hero
- title：90 分钟，从 3 个关键词到能上台的 Demo
- visual：L1 `assets/hero_ui.png`（右侧骑线，占 B 区 45%）
- density：字数约 45 / 图片 1 张 / 留白约 30%
- anti_pattern：禁止居中对称排版；禁止标题压在截图正文上导致不可读；禁止放装饰性小图标
- description：以《人类协议 2100》为唯一案例，讲一次真实的时间盒开发——不是功能介绍，是复盘。

### 02 三句话 · supporting
- title：如果只带走三句话
- layout：左窄标题栏 + 右三条编号条目（01/02/03 巨型序号）
- density：字数约 210 / 图 0 / 留白约 22%
- anti_pattern：禁止三条做成等宽卡片横排；禁止每条只有一句口号没有解释
- description：三条铁律各配一句"为什么"，让人记住因果而不是口号。演示动线先于代码——代码为演示服务；并行前冻结契约——否则并行变返工；稳定性优先于完整性——能演完的 60 分胜过没演完的 100 分。

### 03 案例登场 · supporting
- title：三个随机关键词，长成一个能演的命题
- visual：L1 `assets/shot_mid.png`（左侧，占 42%）
- density：字数约 240 / 图片 1 张 / 留白约 18%
- anti_pattern：禁止 50:50 等分双栏；禁止把截图缩成 200×70 贴片；禁止用文字描述替代真实界面
- description：程序 / 未来 / 人类 → 三个旋钮（技术速率、共情浓度、集体选择）→ 存续指数 + 三条分支 + 一封回信。所有随机关键词都往"一个输入 → 一次处理 → 一个可截图的结果"这个三段式上映射，1331 组参数预生成让静态版零后端可演。

### 04 演示动线 · supporting
- title：先写 60 秒脚本，再写第一行代码
- layout：左侧 4 段时间码（0-10 / 10-40 / 40-55 / 55-60）+ 右侧三个界面状态卡
- density：字数约 260 / 图 0 / 留白约 20%
- anti_pattern：禁止把 60 秒脚本写成功能清单；禁止出现"首页/详情页/设置页"这类多页结构
- description：脚本先定死"谁的问题 → 现场点一次 → 技术一句话 → 下一步"，再反推必须存在的三个界面状态：初始态、处理中、结果态。不服务这三个状态的功能一律不做——这是砍需求时唯一不用吵架的依据。

### 05 契约先行 · supporting
- title：10 分钟写死一份契约，省掉一整轮返工
- visual：CodeBlock（JSON 请求/响应）+ 底部文件所有权条
- density：字数约 230 / 代码块 1 / 留白约 18%
- anti_pattern：禁止把契约写成设计文档；禁止只有字段没有所有权表；禁止代码块与要点各占一半等分
- description：契约只写四件事：JSON 字段名、函数签名、接口路径与示例、文件所有权表。契约一稳，三条线写出来的东西才能直接拼上；契约不稳，并行只会把返工乘以三。

### 06 三线并行 · supporting
- title：并行靠的是文件所有权，不是多开几个会话
- visual：Diagram（A 引擎 / B 服务 / C 前端 → 契约 → 集成者）+ 底部三条禁令
- density：字数约 250 / 图 1（结构图）/ 留白约 20%
- anti_pattern：禁止三列卡片高矮不一；禁止把"集成者"画成第四条并行线
- description：A 引擎、B 服务、C 前端三线同时开工，文件互斥、只依赖契约；集成者不参与并行编码，时间全留给合并与修边界。三条禁令：不并行跑 dev server、不并行装依赖、不并行改同一个文件。

### 07 实测数据 · hero
- title：并行到底快多少？实测两个数字
- layout：巨型数字 2.6× / 1.44× + 对照表 + 洞察
- density：字数约 150 / 图 1（数据对照）/ 留白约 35%
- anti_pattern：禁止把两个数字塞进卡片角落；禁止只给数字不给判断
- description：3 个均衡任务 82s vs 213s，2.6×；含调研的长尾任务 698s vs 1007s，仅 1.44×。判断：并行收益取决于任务均衡度，长尾任务决定总时长——所以拆包时要先把"读代码调研"这类任务单独前置。

### 08 兜底与坑 · supporting
- title：现场一定会出问题，问题要提前变成"已绕过"
- visual：Table（5 个 Light 实测坑：现象 / 处理）+ 洞察框
- density：字数约 240 / 表格 1 / 留白约 15%
- anti_pattern：禁止只列坑不给处理办法；禁止用图标堆代替表格
- description：BOM、CLI 不在 PATH、HTTP 服务端不可用、循环语法、参数来源——五个坑全部有确定解法。兜底三层：前端超时走本地 mock、关键结果预生成、最后一层是提前录好的 60 秒录屏。

### 09 时间盒 · supporting
- title：90 分钟怎么切，以及什么时候必须砍
- layout：横向 5 段进度条 + 下方"熔断顺序"卡与"检查点"卡
- density：字数约 220 / 图 1（进度条）/ 留白约 20%
- anti_pattern：禁止把时间盒画成等分色块却不标检查点；禁止熔断顺序临场讨论
- description：0-10 选题、10-25 空壳跑通、25-60 三包并行出首版、60-75 补三态砍功能、75-90 彩排录屏。熔断顺序固定：登录权限 → 后台多页面 → 花哨动效 → 只留"输入→结果"主线。

### 10 反模式 · supporting
- title：八种翻车方式，和上台前的七项自检
- layout：左 8 条反模式两列清单 + 右侧窄栏自检清单
- density：字数约 300 / 图 0 / 留白约 15%
- anti_pattern：禁止把反模式写成抽象形容词；禁止自检清单用打勾图标堆满
- description：让 TRAE 自由发挥产品方向、边写边加需求、三人改同一文件、现场装依赖、用真实 API 赌网络、把"能跑"当"能演"、追功能数量、密钥进代码。七项自检从构建通过到 git status 干净，逐项过。

### 11 结束 · hero
- title：能演完的 60 分，胜过没演完的 100 分
- layout：居中金句 + 行动三条
- density：字数约 90 / 图 0 / 留白约 45%
- anti_pattern：禁止感谢页式空收尾；禁止出现二维码/联系方式占位
- description：留给现场的三件事：明天挑三个关键词跑一遍 60 秒脚本；下次并行前先花 10 分钟写契约；把兜底当成交付项而不是运气。
