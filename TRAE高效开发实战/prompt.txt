## 作品：人类协议 2100 · 文明推演器
三个关键词是这样用的： 程序 是推演引擎， 人类 是交给它的三个旋钮（技术速率 / 共情浓度 / 集体选择）， 未来 是它给出的 2100 年三条分支、三个转折点，外加一封「来自 2100 年的回信」。

实测一次：技术 20 / 共情 90 / 选择 30 → 存续指数 28、判定「断裂边缘」、断裂带概率 44%，回信是「请你们慢一点，等等还在后面的人。」

## 三项要求
1. 环境搭建 本机 Light v0.4.0（`light.exe` 在源码的`.venv` 里，不在 PATH），Python 3.14.7。`light check` 两个源文件全过；踩到一个坑：文件必须是 UTF-8 无 BOM ，否则报`未知字符 0xFEFF` 。

2. 并行开发 三路同时开工，先冻结 契约.md ，文件所有权互斥：

- A 线： 引擎.light + 自测，15:51 完成，三组自测概率合计均 100
- C 线： web/ 三个原生文件，16:00 完成
- B 线：HTTP 服务写完`check` 通过，但运行时报`创建HTTP服务端 is not defined` ——Light 的 HTTP 服务端在 contrib 里只有 Python 实现，`stdlib` 那套又把端口写死为 0
这是本次唯一一次改方案：传输层换成 60 行的 server.py 薄壳， 推演逻辑仍然 100% 在 Light （ api.light 每次被调用起一个 Light 进程）。

3. Web 页面 深色未来感单页：三个滑块 + 「推演 2100」+「随机一个未来」，结果区有存续指数、三色概率条、时间线转折点、回信卡片；加载态、错误重试都有。浏览器实测：拖滑块、点推演、结果正常渲染，控制台零报错。

## 时间账
15:44 开始 → 16:13 收工， 29 分钟 。其中三线并行到齐用 13 分钟，剩下全是集成与调 Light 的 HTTP 坑。

## 已知限制（上台要讲清楚）
- 概率和文案是 确定性规则推演 ，不是真模型，别说成「AI 预测」。
- 每次请求起一个 Light 进程，约 1 秒，单机演示够用。
- 等服务端进程：`python server.py` ；端口占用就先关旧进程。
如果后面要让评委看到「纯 Light 全栈」，两条路：等他们的 HTTP 模块修好，或把`server.py` 那层用 Light 的`引 Python:` 包回一个`.light` 文件里。需要的话我接着改。
